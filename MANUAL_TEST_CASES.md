# Kaza Shop: Manual Test Cases

## 1. Цель документа

Этот документ описывает полный набор сценариев для ручного тестирования сервиса `Kaza Shop`.

Покрытие включает:

- backend API на уровне пользовательских сценариев
- seller/admin panel
- Telegram-бота покупателя
- оформление и обработку заказов
- уведомления
- статистику
- импорт каталога
- настройки магазина
- типичные, негативные и краевые кейсы

Документ рассчитан на ручной прогон без автотестов.

## 2. Что тестируем

### 2.1 Роли

- Продавец/администратор: работает в seller-panel
- Покупатель: работает через Telegram-бот
- Администратор уведомлений: получает Telegram-уведомления о новых заказах и смене статусов

### 2.2 Функциональные зоны

- Авторизация в админке
- Управление товарами
- Работа с фото товаров
- Каталог в боте
- Корзина
- Оформление заказа
- Управление заказами
- Telegram-уведомления
- FAQ
- Контакты магазина
- Импорт товаров из Excel
- Статистика по заказам и товарам
- Настройки магазина
- Безопасность и ограничения ввода в боте

## 3. Предусловия

Перед началом тестирования:

- Запущены сервисы `db`, `app`, `bot`, `seller`
- Доступен backend: `http://localhost:8000/health`
- Доступна seller-panel: `http://localhost:5173`
- Бот активен и отвечает на `/start`
- В `.env` заполнены:
  - `BOT_TOKEN`
  - `DB_*`
  - `SECRET_KEY`
  - `ADMIN_PASSWORD`
- В настройках магазина заполнен `admin_contact` валидным Telegram ID

## 4. Тестовые данные

Рекомендуемый набор данных:

- Пользователь `buyer_1`: основной покупатель
- Пользователь `buyer_2`: второй покупатель для проверки изоляции
- Telegram-аккаунт `admin_notify`: аккаунт для получения уведомлений
- Категория: `Электроника`
- Подкатегория: `Смартфоны`
- Товар 1: `iPhone 16`, цена `89990`, активный, с фото
- Товар 2: `Galaxy S26`, цена `79990`, активный, без фото
- Товар 3: `Тестовый скрытый товар`, активный = `false`
- Excel-файл для импорта:
  - корректный
  - с пропущенной обязательной колонкой
  - с неверным расширением

## 23. Критерий завершения тестирования

Тестирование можно считать завершённым, если:

- все позитивные кейсы проходят
- негативные кейсы завершаются контролируемой ошибкой без падения сервиса
- seller-panel, backend и bot работают согласованно
- данные синхронизируются между панелью и ботом
- уведомления приходят корректным получателям
- критических блокеров по заказам, каталогу, фото и уведомлениям не осталось
